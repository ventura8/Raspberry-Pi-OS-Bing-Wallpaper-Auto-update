# v1.0.2

## Summary

This release standardizes agent guidance, adds task-specific skills, and automates
GitHub Releases from versioned release notes. No changes to the wallpaper,
installer, or uninstaller runtime behavior.

- `AGENTS.md` is now the single canonical rulebook for coding agents.
- Thin entrypoints for Claude Code and Gemini CLI point into that file.
- Six focused skills under `.agents/skills/` cover quality, tests, coverage, pipeline,
  installer validation, and release preparation.
- Pushing a `v*` tag triggers a workflow that validates `VERSION` and creates the
  GitHub Release from `docs/releases/vX.Y.Z.md`.

## Highlights

### 1. Canonical Agent Rules (`AGENTS.md`)

Replaced the short routing stub with a full project guide covering:

- Product script overview and directory layout
- Mandatory quality/test/coverage gate order (≥90% threshold unchanged)
- Mocking policy and cross-platform constraints
- Agent surface map (skills, Copilot mirrors, docs index)
- **Always Update Agent Docs** requirement when behavior changes

### 2. Multi-Tool Entrypoints

Added thin adapters that defer to `AGENTS.md` instead of duplicating rules:

- `CLAUDE.md` — Claude Code auto-load entrypoint
- `GEMINI.md` — Gemini CLI entrypoint
- `.agent/ai_rules.md` — short AI-agnostic pointer with quality workflow summary

### 3. Task Skills (`.agents/skills/`)

New focused runbooks, each as `SKILL.md`:

| Skill | Purpose |
| --- | --- |
| `quality-gate` | Run and enforce `scripts/quality_checks.sh` |
| `test-runner` | Dockerized bats suites (installer, component, e2e) |
| `coverage-badge` | kcov merge, 90% threshold, badge refresh |
| `pipeline-runner` | Full local pipeline matching CI |
| `installer-tester` | Install/uninstall prompt and cron validation |
| `prepare-release` | Version bump, release notes, docs sync |

Copilot mirrors live under `.github/skills/`; `.github/AGENTS.md` indexes specialist
modes and links back to the canonical rules.

### 4. Automated GitHub Releases

Added release automation and version SSOT:

- Root `VERSION` file holds the released semver (`vN.N.N`)
- `docs/releases/vX.Y.Z.md` is the GitHub Release body source
- New workflow: `.github/workflows/release.yml`
  - Triggers on `v*` tag push
  - Verifies `VERSION` matches the tag and release notes exist
  - Creates the GitHub Release via `gh release create` (title from the notes H1)

README now shows a release badge linking to the current notes file. The release
docs path was corrected from `docs/release/` to `docs/releases/`.

### 5. CI and Quality Gate Alignment

Extended CI path filters and markdown lint scope to cover new agent surfaces:

- `.github/workflows/ci.yml` watches `VERSION`, `CLAUDE.md`, `GEMINI.md`, `.agents/**`
- `scripts/quality_checks.sh` lints the new Markdown paths

Coverage minimum remains **90%**. Local badge refresh via `assets/coverage.svg`
is unchanged — CI validates but does not commit the badge.

## Change Scope

Primary impacted areas:

- Agent documentation and skills (`.agents/`, `.agent/`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`)
- Copilot mirrors (`.github/skills/`, `.github/AGENTS.md`, `.github/copilot-instructions.md`)
- Release automation (`.github/workflows/release.yml`, `VERSION`, `docs/releases/`)
- README and `docs/Instructions.md` release pointers
- CI path filters and quality-check Markdown scope

Product scripts (`bing_wallpaper.sh`, `install.sh`, `uninstall.sh`) are unchanged.

## Validation

- Quality checks cover the expanded Markdown surface via `scripts/quality_checks.sh`.
- Existing bats suites and the 90% coverage gate remain in force.
- Release workflow validates `VERSION` ↔ tag ↔ `docs/releases/vX.Y.Z.md` before publish.

## Notes

- No lint suppressions were introduced.
- Tagging and pushing `v1.0.2` publishes the GitHub Release automatically; no manual
  `gh release create` is required.
